# Animation System (GSAP)

Site animation is **GSAP 3.15.0** (+ ScrollTrigger, ScrollSmoother, SplitText, DrawSVG, MotionPath, Inertia, Physics2D, ScrambleText). WebGL stages use three.js 0.186 or raw WebGL2, and the compact hero's toy box uses matter-js physics. "Heavy animations everywhere" is an explicit design goal, but every animation must degrade gracefully under `prefers-reduced-motion`.

## Setup & conventions

- Plugins registered in `scroll-reveal.ts` (ScrollTrigger) and `smooth-scroll.tsx` (ScrollSmoother).
- **Scroll reveal**: `fadeUpOnScroll(root, selector, {start: "top 85%", stagger, y: 24})` builds one timeline with a **timeline-level** ScrollTrigger, `once: false` plus a kill on complete (`killTriggerOnComplete`, see gotcha #4), which plays once without the `once: true` crash. Under reduced motion it synchronously `gsap.set(targets, {opacity: 1, y: 0})` and returns null (no animation, therefore no race with hover timelines).
- **Smooth scrolling**: `<SmoothScroll>` in the root layout wraps every public page in `#smooth-wrapper`/`#smooth-content`, but only `/` gets a live `ScrollSmoother` (`smooth: 0.75`), and never under reduced motion. Every other route scrolls natively. `/admin` and `/forms` get bare children. Inside `#smooth-content` (a transformed box) `position: fixed` and `position: sticky` don't work: render fixed layers through a portal into `document.body`, and build a "sticky" hold from scroll math (the reel's pin does).
- **Reduced motion**: components check `matchMedia("(prefers-reduced-motion: no-preference)")`. The pattern is `const d = reduced ? 0 : 1;` and multiplying durations by `d`, timelines still run (content must stay reachable) but collapse to instant swaps. Decorative loops (idle breathing, social wiggle) are skipped entirely under reduced motion.
- **Hydration-safe clock** (`"--:--"` server-side, real time in effect) is the pattern for any time-dependent UI.
- **React 19**: refs pass as props (`ref={ref}`) on function components, not `forwardRef`.

## Gotchas (each of these has already cost real debugging time)

### 1. Never let a CSS class set transform on an element GSAP animates

GSAP **stacks onto** a pre-existing CSS-class transform instead of replacing it (observed twice: `translate-y-full` made a `yPercent` tween a no-op; a static `[transform:translateX(100%)]` class compounded with GSAP's `xPercent` to a 200% offset: computed style was literally `translate(100%,0%) translate(460px,0px)`). Tailwind v4's `translate-x-full` sets the separate CSS `translate` property: same failure mode.

**Rule:** GSAP must be the _only_ thing touching `transform`/`translate`/`rotate`/`scale` on an element, from first paint on (explicit `gsap.set()` in a mount effect). For pre-hydration "hidden" defaults use **opacity/visibility only** (`invisible opacity-0`: GSAP's `autoAlpha` cleanly overrides them).

### 2. `.fromTo()` renders its "from" state at creation (`immediateRender: true` default)

Even inside a `paused: true` timeline, creating a `.fromTo()` immediately applies the "from" values. Under reduced motion all durations collapse to 0, so "from" and "to" are the same instant. Every card snapped to its hovered state **on mount, before any hover**. Fix: `immediateRender: !reduced` on such tweens. (`immediateRender` cannot be part of `defaults`. It's per-tween. Also note: `defaults: {immediateRender: false}` does not work reliably across GSAP versions; set it explicitly per tween.)

### 3. Hover-vs-entrance races: use `.fromTo()` baselines, not `.to()`

When a hover timeline and a scroll entrance (or idle loop) animate the **same property of the same element**, a plain `.to()` adopts "current value" as its implicit start. Hovering mid-entrance lets `overwrite: "auto"` kill the entrance at a partial value, and reversing the hover timeline returns to that **stuck half-finished value forever**, the famous Core Competencies bug (cards stuck lower than the others, sometimes `opacity: 0`).

**Fix pattern** (see `core-competencies.tsx`, heavily commented): build the hover timeline with `.fromTo()` specifying the true rest baseline (`{y: 0, opacity: 1}`, `{scale: 1}`), `immediateRender: !reduced`. Reduced motion doesn't need the protection (its entrance is a synchronous `gsap.set`, already resolved before any hover).

### 4. ScrollTrigger: use timeline-level triggers, not tween-level

GSAP 3.15.0 throws inside ScrollTrigger's internal refresh when a **tween-level** `scrollTrigger` is created after ≥4 other ScrollTriggers exist on a page that loaded already scrolled down (for example, reload mid-page). `fadeUpOnScroll` deliberately builds a timeline with a timeline-level trigger (`gsap.timeline({ scrollTrigger: {...} })`). Don't regress to `gsap.fromTo(el, {...}, { scrollTrigger })` on this codebase.

A second, subtler 3.15.0 crash lives in the same refresh loop and does NOT require a tween-level trigger: when several timeline-attached triggers mount on a page already scrolled down, the first scroll event force-initializes the still-unrefreshed triggers inside `refresh()`'s own loop over the trigger registry. A `once: true` trigger scrolled fully past its end calls `self.kill()` right there, splicing the registry mid-iteration, and the loop reads `.end` off `undefined` ("Cannot read properties of undefined (reading 'end')"), which unmounts the page tree. Timeline-level triggers are NOT immune to this one. The fix that shipped is `once: false` plus `killTriggerOnComplete` (see the Known issues section): same visible behavior, registry mutation moved out of `refresh()`. Never reintroduce `once: true` on a trigger that can mount while the page is already scrolled past its end.

### 5. SSR flash prevention (server HTML has no JS)

Anything hidden only by a mount-effect `gsap.set()` flashes visible on first paint / reload. Give closed-state defaults via static classes (opacity/visibility only, gotcha #1), and let the mount effect position the rest. Verified with a `javaScriptEnabled: false` Playwright context: server HTML must show nothing of the closed panel.

### 6. Panels inside collapsed clips

A panel mounted inside a `height: 0` accordion clip can't establish its starting transform value. `gsap.to(panel, {yPercent: 0})` may no-op. Set the start explicitly with `gsap.set(panel, {yPercent: 100})` on mount (see `work-bento.tsx`).

### 7. Stacking contexts & z-index under transforms

GSAP's transform creates its own stacking context, so a child with a stray `z-10` can paint over a sibling overlay that animates in later (observed: front title painting over the Our Work reveal panel, fixed by removing the z-10). Keep z-index flat inside animated subtrees.

### 8. A GSAP-owned CSS property can't also be styled by a stylesheet rule

Any tween's end state is an **inline style** (`element.style.opacity = ...`), and inline styles beat every stylesheet rule on the same property regardless of selector specificity, `!important` aside. `fadeUpOnScroll` leaves `opacity: 1` sitting in `style` on every revealed element forever, so a later stylesheet rule that also targets `opacity` on that element (for example, a filter/dimming feature keyed off a data attribute) silently no-ops on anything that already played its entrance. **Rule:** if a feature needs to style a property from a plain stylesheet rule, make sure no GSAP tween anywhere on the page ever sets that same property inline on the same elements. Pick an untouched property (`filter`, a custom property consumed by `filter`/`background`, etc.) rather than fighting inline-style specificity.

### 9. `loading="lazy"` doesn't work on content moved by a continuous transform

An element repositioned every frame by an imperative `element.style.transform` (rAF loops, not real document scroll, for example `about/drift-wall`'s per-column tracks) can sit genuinely off-screen at mount even though it will drift into view seconds later. Native lazy-loading only fetches an image once it's actually within the viewport-distance threshold, so tiles that start off-screen don't even begin fetching until the drift carries them in, for a slow, minutes-long loop this reads as permanently broken/blank content. Measured on the team wall: `loading="lazy"` loaded 29/228 images after 3.5 seconds; `loading="eager"` loaded 228/228. **Rule:** any image inside a perpetually animating, off-screen-by-design container should be `loading="eager"`. The component already only mounts once its section scrolls into view, so there's no real lazy-load benefit being given up.

### 10. A bare `ScrollTrigger.create()` is the same forbidden shape as a tween-level trigger

Gotcha #4 says to use a timeline-level `scrollTrigger`, not a tween-level one, but a **standalone** `ScrollTrigger.create({ trigger, start, onEnter, onLeaveBack })` with no tween or timeline attached at all hits the exact same GSAP 3.15.0 internal-refresh bug. Found in `sections/cta-footer.tsx`'s `BackToTop`: it called `ScrollTrigger.create()` directly, and since `CtaFooter` remounts on every client-side navigation, this fired on almost any route change once ≥4 other ScrollTriggers already existed on the destination page: an uncaught `TypeError: Cannot read properties of undefined (reading 'end')` inside GSAP's own `refresh()`, with no error boundary in this app, meaning Next's dev error overlay (or a blank prod page) and a required reload. **Fix:** wrap the exact same config in an empty timeline instead, `gsap.timeline({ scrollTrigger: {...} }).scrollTrigger`, and use that returned `ScrollTrigger` instance for cleanup (`.kill()`). `onEnter`/`onLeaveBack` behave identically either way. Confirmed with a scripted navigation fuzzer (random scroll + click across every route, watching for `pageerror`): 1 crash in 51 navigations before the fix, 0 in 136+ after.

### 11. A `once: true` ScrollTrigger doesn't fire retroactively if it mounts already past `start`

`onEnter` (and therefore the entrance timeline `fadeUpOnScroll` builds) only fires on an actual **forward crossing** of the trigger's `start` position, not on creation, even if the current scroll position is already past it. On a client-side navigation, a page's data-fetched sections (and the `RevealSection`/`fadeUpOnScroll` call wrapping them) can mount several commits after the route change, by which point the visitor may already be scrolled past where that trigger's `start` would be. No crossing event ever happens, so the timeline silently never plays, and the section, most visibly the shared footer's `.footer-reveal` content, stays at its `opacity: 0` "from" state forever. Reproduced most easily via a bounce navigation (leave the page, come back) followed by scrolling straight to the bottom before the new page's triggers exist yet.

**Fix** (see `lib/scroll-reveal.ts`): the check is re-armed and runs through several converging routes instead of once at creation. A synchronous creation-time read is nearly useless anyway (timeline-attached triggers defer their position calculation to the next tick, so `progress` reads `undefined` right after creation). The working routes are: ScrollTrigger's own "refresh" event (fired at the end of every batched refreshAll, after image-load layout shifts, and after the smoother settles), two delayed fallbacks (250 ms / 750 ms) that re-read the trigger once its positions exist, and a final DOM-measured fallback (1.5 s) that needs no ScrollTrigger internals at all, so it still resolves the section when the batched refresh aborted mid-way (see the `once` self-kill crash in gotcha #4). Each route jumps straight to the resolved end state (`tl.progress(1)` plus a defensive `gsap.set`) only when the reveal has not started at all (`tl.progress() === 0`) and the trigger reports a positive progress. A killed trigger (unmount) resolves all routes as handled without touching the DOM.

**A fix that made this worse, for the record:** an explicit `ScrollTrigger.refresh()` scheduled at a few delays after every route change (to catch triggers created before their content had visually settled) was tried and reverted. It turned a 28-repro baseline into 36, including a full-section cascade failure (every reveal on `/about` stuck at once). Recalculating trigger positions while other triggers are still mid-setup is worse than not recalculating at all; don't reach for a blanket `refresh()` here.

### 12. Effect order: a parent's ref and a later sibling's registrations don't exist yet

React runs layout effects children first, and earlier siblings before later ones. A child's layout effect therefore runs before its parent's ref is attached (the `/projects` card halves read `rootRef.current` as `null` on mount and silently skipped their hover wiring), and a component rendered before a list runs its effects before the list's items have mounted (the cover stage's eager-loading loop found no cards). Find the parent from the child's own element (`closest("a")`), or subscribe to registrations instead of reading them once.

### 13. A JS scroller must clean up in a layout effect

A passive (`useEffect`) cleanup runs after the next route's layout effects. `smooth-scroll.tsx` resets the scroll to the top in a layout effect on every route change, so a still-gliding Lenis cleaned up in a passive effect wrote the old position back and the next page opened scrolled down. The `/projects` stage host uses a layout effect for exactly this reason.

### 14. A timeline `.to()` without a position is appended after the timeline's end

Not after the previous call: after the longest tween so far. A focus pulse chained after a 1.5 s zoom played a second late. Chain beats with `">"` or explicit times.

### 15. The dash pattern restarts at every subpath of a `<path>`

In Chromium, WebKit and Firefox alike, so DrawSVG on a multi-subpath path can't retract one segment (a `"44.5% 100%"` retract collapsed the arrow to a dot). Split the segments you animate into separate paths.

### 16. `gsap.quickTo` and `gsap.quickSetter` silently ignore the `scale` shorthand

Drive `scaleX` and `scaleY` separately.

### 17. A fixed canvas drawn against native scroll trails the DOM by a frame

The compositor scrolls the page before the next animation frame redraws the canvas. Scroll from JS (Lenis) and draw in the same tick, after the scroll step (`projects/stage/frame-loop.ts`).

### 18. Timers keep running in a hidden tab while animation frames stop

The GSAP ticker freezes, `setTimeout` doesn't. A failsafe that releases choreography after N seconds must count visible time only, or a tab opened in the background releases the list over an entrance nobody has seen (`projects-hero.tsx` and `projects-grid.tsx` pause theirs on `visibilitychange`).

### 19. ScrollTrigger owns `history.scrollRestoration`

It saves the mode when it registers and writes it back on every refresh, so a plain assignment gets reverted. Change it through `ScrollTrigger.clearScrollMemory(mode)`.

### 20. Scrolling fires mouseenter on whatever slides under a resting cursor

In every engine. Hover effects that shouldn't play mid-scroll must wait for the scroll to settle (`projects/stage/scroll-idle.ts`). Related: `gsap.matchMedia().revert()` never removes the change listeners it added, so per-visit setup should use `window.matchMedia` lists with explicit listeners (`projects/hero-play.ts`), and `inert` in server HTML can't be undone by a `<noscript>` style override, so set it from JS.

### 21. Two scroll resets run after a page's own layout effects

A page that restores its scroll position in a layout effect on arrival loses it twice. The root layout's `smooth-scroll.tsx` jumps every new route to the top in a layout effect of its own, which runs after the page's (a parent after its children). Next's scroll to top on a push runs from `componentDidMount` in its layout router, also after the page's layout effects. The project list's return mode needs both to stand down: `skipScrollReset("/projects")` before the navigation (consumed by the smooth scroller, and used up by any route change so it never leaks to another page) and `router.push(href, { scroll: false })`. A native link click can't pass `scroll: false`, so the reduced-motion restore repeats itself one animation frame later.

### 22. A route committed under a fading overlay shows through it

The project zoom first pushed the route as soon as its first frame was up, like the curtain does. With the payload already cached from an earlier visit, the project page committed about 0.3 s into the zoom, while the theme colour layer was still mostly transparent, and it replaced the list visible around the zooming quad. Change the route only once whatever covers the page is opaque, and prefetch the payload at the click (`router.prefetch(href, { kind: "full" })`, since a dynamic page without `loading.tsx` is otherwise not prefetched) so the late push commits at once.

### 23. A CSS transition on a property a per-frame tween also drives lags it

The glass header eases its colours over 0.5 s in CSS, and the project zoom walks the same colours every frame through custom properties. The header follows the walk as if low-pass filtered, about 0.3 s behind. End such a walk early (the zoom's ends by 80% of the way in) or remove the CSS transition for the duration.

### 24. A shared geometry can't carry instanced attributes of different counts

Two `InstancedMesh`es built on one `BufferGeometry` with per-instance attributes of different lengths fail to draw (a WebGL draw error, and nothing on screen). Clone the geometry for an instanced mesh whose attributes differ (`plane.clone()` for the fog sheets in `library/atmosphere.ts`). Sharing is fine when every mesh has the same instance count, as the two walls in `library/stacks.ts` do.

### 25. A transition that owns a shared scene must also own what the route would have changed

The articles world skips its own route dressing (the lens amount, whether the list's cards draw) while a transition is busy, so a route change mid-transition can't fight the choreography. The flip side: whatever the route would have changed, the transition must set itself. The first close transition brought the list back with no cards at all, because the article page had hidden them and the world waited for the busy flag to clear. `article-transitions.ts` now shows the cards when the list comes in and hides them when the article does, and its `finish()` leaves the world as the landed route wants it.

### 26. A long camera pan carries the camera off the set

Panning the camera 2800 px (unseen's list-to-project pan) carried it out through the library's wall, and the close transition showed the bare back of a bookcase. Move the set with the pan, all but a parallax that eases out as it nears a safe reach (a share of the set's width, `tanh`), so the depth still reads and the camera stays inside on every screen.

### 27. A frame-time clock stretches every beat on a slow renderer

A clock that adds each frame's time capped at 0.5 s (so a single hitch doesn't jump the animation) runs slow when every frame is slow: on CI's software-rendered Linux WebKit the portal's cover was still playing five seconds after a click. Keep the frame clock for the animation, bound every beat in real (visible) time as well, and tick the run from a timer while frames stop coming. GSAP timelines have the same problem through lag smoothing (at most 33 ms of timeline per frame over 500 ms): the articles transitions push each timeline's playhead forward from a timer (`paced` in `article-transitions.ts`). And when frames are that slow for good, the articles world gives the visit to its DOM version (`HopelessWatch` in `articles/world/quality.ts`).

### 28. Motion blur taps that share the lens's spectral weights smear into rainbows

The list's first motion blur reused the chromatic split's per-tap weights, so a fast scroll smeared every edge into a rainbow. Shuffle the blur taps against the split (a golden-ratio offset), keep the smear short (0.0075 of the scroll speed, clamped to `MAX_BLUR` in `engine.ts`), and let the split stay a lens effect at the edges.

### 29. A touch press must commit on a finished tap, never on `pointerdown`

A finger's `pointerdown` fires before the browser decides the gesture is a scroll, and a scroll then ends it with `pointercancel`. The hero first pressed on `pointerdown` for every pointer type: a scroll swipe that started on the toggle switched it, and one that started on empty space threw a burst. Mouse and pen still press on `pointerdown`. A finger presses only on a `pointerup` that moved under `12 px` and was never cancelled, and the press then lets go after `0.12 s` (`hero/interactions/index.ts`). The magnets follow the same rule the other way round: a quick swipe scrolls, a hold of about `180 ms` picks the magnet up, and a tap flips it.

### 30. A box cached until the next scroll event goes stale under ScrollSmoother

The native scroll events stop when the wheel stops, but ScrollSmoother keeps gliding `#smooth-content` for a while after. `attachMagnetic` (`lib/motion/magnetic.ts`) used to measure an element's box once and drop it on `scroll`. A pointer move during the glide cached a box from mid-glide, and after that a cursor `30 px` from a link pulled it by 0 instead of 10 until the next scroll. It now measures at most once a frame, subtracting its own pull (`gsap.getProperty(el, "x")`). Anything on `/` that caches a rect for pointer maths must measure per frame, or invalidate from a `gsap.ticker` callback while the smoother is still moving.

### 31. An auto-scroll must arm only on real input, and gate on the native position

The reel's snap (`reel/reel-controller.ts`) keeps the page moving when a visitor stops mid-morph. It is armed only by input the visitor gave: a wheel (not a pinch, `ctrlKey`), a key that scrolls (arrows, Page Up and Page Down, Home and End, Space off a button), a touch drag, a drag on the classic scrollbar (a mouse press at `clientX >= clientWidth`), and keyboard focus landing in the section (`:focus-visible`: the play button snaps forward, the CTA snaps back). Escape and lone modifier keys are neutral, so closing the menu or the player leaves a snap alone. Any other key (Tab) stands it down. A scroll nobody asked for (`scrollIntoView`, `ScrollSmoother.scrollTo`, an anchor, a script) disarms it once `600 ms` have passed since the last real input, so e2e specs that scroll programmatically are never carried off. Under `isScrollLocked()` or while the player is open it stands still, and a snap the menu or the player paused resumes when the lock lets go (scroll events within `400 ms` of a lock change are ignored). It drives and reads the native scroll position, not the smoothed one: at one viewport per second the smoothed position lags by hundreds of pixels, so a snap that stopped on what is on screen would glide straight through the hold. Known edge: within `600 ms` of the last real input, a scripted scroll into the morph range is still carried.

### 32. Draggable forces `touch-action: none` on its target and every descendant

Draggable's x/y mode sets it (around line 2745 of `Draggable.js`), so a page can't be scrolled by a swipe that starts on a draggable element. The magnets need both: a swipe scrolls, a hold picks up. They use a small pointer controller instead (`process/magnet-board.ts`), with `touch-action: pan-y`, a non-passive `touchmove` that calls `preventDefault()` only once a magnet is held, InertiaPlugin for the throw and MotionPathPlugin for the flight home.

### 33. A canvas behind the page can't be a `body > canvas` if the articles portal must leave it

The articles portal takes every `body > canvas` except the library's own as a layer of the page it lifts, and drains it with the page (`transition/articles-portal-stage.ts`). That suits a canvas drawn over the page (the WebGL covers), not one behind it. The cursor flow's canvas therefore sits inside its own box, `div[data-cursor-flow-layer] > canvas[data-cursor-flow]` (appended to `<body>`, `z-index: -1`), which that selector skips, and the flow steps aside by itself while an articles transition is busy, so the portal's arch shows around the sheet exactly as it does without the flow. Anything that selects `body > canvas` won't find it. The reel's fallback stage (`canvas[data-reel-gl-canvas]`, used only when the flow isn't up) is a direct child of `<body>` and is lifted with the page like any other.

### 34. Open a video with sound synchronously inside the click

`openReelPlayer()` (`lib/reel-player.ts`) must be called from the native click handler itself, which also covers Enter and Space on the button. The host builds its `<video>` inside that call, so the browser counts the user activation and allows sound. A call from a later ticker frame loses the activation: the player then opens paused on its big Play button, and iOS plays no sound.

### 35. Never add an attribute to server HTML before React has hydrated it

A streamed page hydrates its sections after the cursor flow may already be up. The flow's first surface scan marked unhydrated sections with `data-flow-clear`, and React reported a hydration mismatch on `/member`. `flow-surfaces.ts` now marks only elements that carry React's `__reactFiber$` key, retrying every `400 ms` for about five seconds. The same applies to any script that decorates the DOM from outside React.

## Cursor flow

The cursor flow runs on every public route, not only on `/`. `CursorFlow` (`cursor-distortion/cursor-flow.tsx`) is mounted by `components/smooth-scroll.tsx` on every public route, with `active` false on project detail pages and in the articles library (they draw cursor effects of their own). `flow-controller.ts` owns one stage for the whole visit: hiding it on those routes releases its big buffers, and returning shows it again, already compiled.

- **Who gets it.** A fine pointer, motion allowed, and a hardware WebGL2 context: a software renderer is rejected by its renderer string (SwiftShader, llvmpipe and similar), and one that hides its name by a timed warm-up frame. A slow renderer or a lost context hands the page back to plain CSS for good, and so does reduced motion switched on mid-visit. Everyone else never loads it.
- **When it loads.** Never in the first chunk: the engine and three.js are imported once the browser is idle after load, or soon after the first mouse move.
- **The stage.** `flow-engine.ts` appends `div[data-cursor-flow-layer]` (fixed, `z-index: -1`, `pointer-events: none`, `aria-hidden`) holding `canvas[data-cursor-flow]` to `<body>`. The DOM, text included, paints over it. It draws the page colour, then `host.scene`, then the distortion. Pixel ratio is capped at 1.5, with a total cap of 2560x1440 pixels. Rendering stops after `1.2 s` without a stamp, with no scroll and no layer holding frames, and in hidden tabs.
- **The field.** A 1/4 resolution RGBA8 render target, ping-ponged (8-bit on purpose: the 8-bit limits and the `0.004` weight floor are part of the look). RG is the velocity around 0.5 (a leaky integral of the brush's motion, `x0.975` per step), B the slow weight (`x0.95` per step) and A the fast weight (`x0.8` per step). A blurred 9-tap copy at 1/8 resolution steers the self-advection (a push of 25 texels) and a noise warp (scale `0.02`, strength 3). The brush is a capsule of radius `min(max(40, vw / 20), 0.72 x px moved this step)`; a jump over `360 px` or leaving the window starts a fresh stroke. Scrolling carries the field with the content, and a still cursor paints a light comet while the page scrolls.
- **The composite.** Nine samples of the stage along `-velocity x weight`, `3.75` paint texels a step, with a per-frame hashed noise jitter, plus an additive `sin(velocity)` sheen where the paint has faded (strength 12.5 in light, 16 in dark with a small pull toward grey). It runs every display frame; a `uFieldShift` uniform keeps the trail on the content during frames where no step ran.
- **The fixed step.** Every constant is lusion's `60 Hz` per-frame value, and the field advances on a fixed `60 Hz` clock: steps owed are counted by round and carry, at most 3 per display frame. Scaling per-frame constants by `k^(dt*60)` instead does not reproduce the look on a `120 Hz` screen (the 8-bit rounding and the advection count frames). Measured, a `106 Hz` run decays the same as a `60 Hz` one at the same millisecond marks.
- **Surfaces.** `flow-surfaces.ts` sets `html[data-flow]` and marks every full-width surface whose own background is exactly the page colour with `data-flow-clear`; one unlayered rule in `cursor-flow.css` makes marked elements transparent, and since the canvas paints the same colour, the page at rest is pixel for pixel what it was. Never cleared: the footer, anything narrower than 90% of the viewport, fixed and sticky boxes, anything inside a surface of another colour or with a background picture, and anything marked `data-flow-keep` (add it to a full-width page-colour surface that must stay opaque). The body keeps its background, so the header's tone probe still reads the page colour. A rescan (theme switch, new content, resize, throttled to one per `250 ms`) sets `html[data-flow-scan]` to turn the rule off, reads the true colours and removes it in the same task, then reports any page-colour change to the engine and asks the header to sample again. Every marker is removed on teardown.
- **Page shells.** When the first opaque full-width box holds the page (it contains the footer, or is at least 90% of the content height) and is at least 75% of the view tall, its colour becomes the page colour: the stage paints it, the shell clears, and a header tone provider hands the glass header that colour. This shows the flow on `/events`, `/careers`, `/research`, `/publications` and `/projects`.
- **The `GlHost` contract** (`lib/gl-host.ts`, types and a tiny registry only, so importing it never pulls three.js into a first chunk). The stage registers itself with `setGlHost()` while shown; a layer finds it with `onGlHost(listener)` (called now and on every change) or `getGlHost()`. `scene` is drawn before the distortion, so everything in it is smeared. `camera` is orthographic in CSS pixels, x right from the left edge and y UP from the top edge, so a DOM rect maps to a plane centred at `(x + width / 2, -(y + height / 2))`. `paintTexture` (stable across frames, or null) is the field above, sampled in screen UV. `size` holds the viewport in CSS px and the pixel ratio. `onFrame(listener)` runs every frame after the page's scroll has moved the DOM (ScrollSmoother included) and before the render, so rects read there match the screen. `requestFrames(owner, active)` keeps frames on while a layer animates (a playing video). Colour is display-referred: set material colours with `color.setHex(hex, LinearSRGBColorSpace)` and leave video and image textures in `NoColorSpace`, and they draw the same bytes as the DOM.
- **Dev flags** (development builds only, except `?noflow`): `?flowgrid` draws a debug grid, `?flowdemo` mounts a textured plane (`flow-demo.ts`) that proves layers are smeared and stay glued to their DOM box, and `?noflow` turns the flow off for that visit. `window.__cursorFlow.engine` offers `debugState()`, `debugReadField()`, `setFrozen()` and `debugTune()`.
- **Traps.** Mark surfaces only after hydration (gotcha #35). The shell rule needs its footer-or-90% test, or a coloured hero band or a section of its own colour would be taken for the page and recolour the whole stage. The canvas lives in its own box, so `body > canvas` selectors skip it (gotcha #33). Use the fixed step, never `k^(dt*60)` scaling. On the dev server `/about` can show the flow about `26 s` late: HTTP/1.1 queues its member photos ahead of the engine chunk, which production's HTTP/2 does not.

## Known issues

- **Rare reveal miss / whole-page blank on non-homepage routes** (issues #62 and #63): reproduced with a scripted fuzzer that navigates via the menu and jumps to the bottom while the curtain is still covering, the failure turned out to be a GSAP 3.15.0 internal crash, not a positioning race: when several timeline-attached triggers mount on a page that is already scrolled down, the first scroll event force-initializes the still-unrefreshed triggers inside `refresh()`'s own loop over the trigger registry. A `once: true` trigger scrolled fully past its end kills itself inside that loop, splicing the registry mid-iteration, and the loop then reads `.end` off `undefined` ("Cannot read properties of undefined (reading 'end')"). The uncaught error unmounts the page tree, leaving the header and blank content until a reload. Fixed by replacing every `once: true` trigger with `once: false` plus a kill-on-complete callback (`killTriggerOnComplete` in `lib/scroll-reveal.ts`): the visible behavior is identical, but the registry mutation now happens from the ticker instead of inside `refresh()`. The conversion covered `scroll-reveal.ts`, `about/bauhaus-field.tsx`, `focus/shared/focus-pipeline-section.tsx`, and the homepage's own triggers (Trusted By, and every trigger the remade homepage adds: the magnets' entrance, the kinetic headings). Confirmed 0 crashes across 150 scripted navigations after the fix versus a reproducible crash before it.
- **Rare (~1%) reveal miss on the homepage specifically**, tied to its `ScrollSmoother` instance tearing down and recreating across navigation away from and back to `/` (recall: `shouldSmooth = pathname === "/"` in `smooth-scroll.tsx`, so `/` is the only route with a live `ScrollSmoother`). The re-armed catch-up in `fadeUpOnScroll` (see gotcha #11) covers the smoother's late settle, and no homepage trigger uses `once: true` any more. Homepage entrances that build their own trigger (the magnets, the kinetic headings) copy the same catch-up: the refresh event, the `250 ms` and `750 ms` timers, and the DOM check at `1.5 s`.
- **PDF viewer toolbar / mobile keyboard focus**: fixed as of the mobile-responsive-audit work (see `docs/testing-verification.md`'s regression checklist), noted here only so a future CSS `order-*` change on `publications/pdf-viewer-dialog.tsx`'s header doesn't reintroduce it. Visual (wrap) order and DOM (tab) order must stay in agreement; prefer reordering the DOM over `order-*` when the two would otherwise diverge.
