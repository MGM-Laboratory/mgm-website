# Testing & Verification

**Rule: nothing is "done" until it's been seen working in a real browser.** The established workflow is Playwright (screenshots + interaction scripts) against the dev server, followed by `open http://localhost:3000` for a human look. The dev server must stay running at all times (`pnpm dev:web`); check with `curl -s -o /dev/null -w "%{http_code}" http://localhost:3000` before and after changes.

## Playwright methodology (proven patterns from this codebase)

- **SSR / flash checks**: a browser context with `javaScriptEnabled: false` shows exactly what server HTML renders, used to prove the nav menu's reload-flash fix (nothing of the closed panel may be visible pre-hydration).
- **Computed styles**: sample `getComputedStyle(el).transform/opacity` before/after interactions to verify GSAP end states, for example confirming the Our Work panel actually moved (it had silently no-op'd once).
- **Animation-timing races**: drive `page.mouse.move()` directly (no `hover()` sugar) to hit precise mid-animation windows, for example hovering a Core Competencies card immediately after the section scrolls into view.
- **Stress tests**: repeat a race repro many times (12× single-card, then 4 cards × 5 timing windows × many runs). The Core Competencies race only showed intermittently; a single pass proves nothing.
- **Emulation**: `reducedMotion: "reduce"` (all reduced-motion paths: mount state, hover/unhover swaps, no snap-to-hovered on mount) and `colorScheme: "dark"` (menu text visibility was a real bug once).
- **Viewport matrix** for the no-scroll menu: 1280×800, 1440×900, 1280×600, mobile 390×844, with both dropdowns open: verify no scrollbar and nothing clipped.
- **`reducedMotion: "reduce"` is required for a `fullPage` screenshot to mean anything on this codebase, not just a nice-to-have.** Every `fadeUpOnScroll`-driven section (which is most of the page, on most pages) starts at `opacity: 0` and only reveals on an actual scroll crossing. A `fullPage` screenshot taken without emulating reduced motion captures the page in whatever mid-animation state it happened to be in, which on a first pass can look like "half the homepage is blank" and isn't a real bug at all. Confirmed the hard way during the mobile-responsive audit: an entire first round of ~84 screenshots had to be thrown out and recaptured with `reducedMotion: "reduce"` for this reason. It has a second benefit specific to this codebase: `ScrollSmoother` (see `docs/animation-system.md`) is never created under reduced motion, so it also removes the transform-wrapper interference that otherwise breaks a plain `document.body.scrollWidth` overflow check.
- **Per-element overflow probe, not just `document.body.scrollWidth`**, when hunting for horizontal-scroll bugs: comparing `scrollWidth` to `clientWidth` tells you _that_ something overflows but not _what_. A `getBoundingClientRect()` sweep over every element, filtered to `rect.right > viewportWidth`, sorted by overflow amount, finds the actual offending element in one pass, but expect noise from elements deliberately clipped by an ancestor's `overflow-hidden` (this design system uses full-bleed decorative shapes that spill past their own container on purpose); a genuine bug still needs the `scrollWidth > clientWidth` check to confirm it's not just clipped.
- **A closed-form "scroll to the bottom" beats a fixed number of `mouse.wheel()` calls** when scripting repeated page visits: a fixed iteration count can silently under-scroll (smooth-scroll CSS, animation timing, or simply not enough iterations for an unexpectedly tall page all cause this) and produces false "stuck/invisible content" reports that are actually just "the script didn't scroll far enough to see it." Poll `window.scrollTo(0, document.documentElement.scrollHeight - clientHeight)` in a loop until the resulting `scrollY` stops advancing, rather than looping a fixed number of times.
- **Regenerating a Playwright visual-regression baseline: use the exact CI browser image, or better, pull CI's own output.** A local run, even via Docker with the exact pinned `mcr.microsoft.com/playwright:vX.Y.Z-<distro>` image, can still render subtly differently from the actual GitHub Actions runner (observed: a homepage baseline came out 6076px tall locally vs. 4454px tall on real CI, for reasons not fully root-caused, possibly the Projects section's WebGL slider or some other GPU/software-rendering difference). The reliable fix is to pull the _actual_ `-actual.png` bytes a failed CI run produced (download the `playwright-report-<os>-<project>` artifact, extract its embedded zip: `grep -o 'data:application/zip;base64,[A-Za-z0-9+/=]*' index.html`, base64-decode, unzip. Then match the failing test's `testId` in its `<fileId>.json` to find which `data/<sha1>.png` is `*-actual.png` vs `*-expected.png`) rather than trying to reproduce CI's environment exactly.
- **Scripted navigation fuzzing catches intermittent bugs a single manual click-through won't.** For "sometimes X breaks" reports (an uncaught exception on some navigations, content occasionally stuck invisible), a Playwright script that repeatedly clicks real `<a href>` navigation links across every route in random order, with a random pre-navigation scroll amount, while listening for `page.on("pageerror", ...)`, reproduced a crash that a first, smaller run (51 navigations) caught only once, confirming a fix needs re-running at a larger scale (100+ navigations) before trusting a "0 repros" result. A fix suspected of interacting with animation timing should always be validated this way rather than by feel.

## Regression checklist (bugs that have shipped before)

| Bug                                                                     | What to re-check when touching related code                                                                                                                                                                                       |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Menu flashes open on reload/first visit                                 | No-JS context must show a fully invisible panel; reload repeatedly                                                                                                                                                                |
| Core Competencies cards stuck lower / invisible after hover             | Hover each card at several moments during the entrance animation; repeat many times; also under reduced motion                                                                                                                    |
| Reduced-motion snap-to-hovered on mount                                 | With `reducedMotion: "reduce"`, cards must mount at rest (`y: 0`, `opacity: 1`, back content hidden)                                                                                                                              |
| Menu text invisible in dark mode                                        | Dark-mode screenshot of the open menu                                                                                                                                                                                             |
| Menu scrolls / content clipped                                          | Viewport matrix above, both dropdowns open                                                                                                                                                                                        |
| Dropdown panel doesn't move on hover                                    | Computed transform before/after hover (yPercent must actually change)                                                                                                                                                             |
| Double text on Our Work hover                                           | Front title must not paint over the reveal panel (no stray z-10)                                                                                                                                                                  |
| GSAP + CSS transform stacking                                           | Computed style must never show compounded `translate(...) translate(...)` (gotcha #1 in `docs/animation-system.md`)                                                                                                               |
| Uncaught exception on client-side navigation                            | A scripted navigation fuzzer (see above) with `page.on("pageerror")` across every route, 100+ navigations, 0 errors expected (gotcha #10 in `docs/animation-system.md`)                                                           |
| Content (especially the shared footer) stuck invisible after navigating | Bounce navigation (leave a page, come back) then scroll straight to the bottom before content settles; check computed `opacity` on `.footer-reveal`/`.reveal-item` (gotcha #11 in `docs/animation-system.md`)                     |
| `/projects` list shown, clickable or scrollable during the intro        | 10 reloads (half from deep in the page) and internal navigation via a real link: `html` overflow hidden and the list at opacity 0 and `inert` until the hero entrance ends, then the list fades in. See `docs/projects-page.md`   |
| `/projects` cover left blurred, zoomed or clipped                       | Scroll the whole list slowly and with flicks, then back up and down again, and hover cards while scrolling: every cover ends sharp at rest (read `window.__projectsStage` in dev), no card shows its DOM and WebGL covers at once |
| PDF viewer toolbar visual order diverges from keyboard tab order        | Tab through the open PDF viewer at &lt;640px and confirm focus moves top-to-bottom, matching what's visually first. Don't reorder with CSS `order-*` without reordering the DOM to match                                          |

## Type & lint gates

`pnpm typecheck` (web: `next typegen && tsc --noEmit`) and `pnpm lint` (web: eslint; api: oxlint) must be clean before declaring done: these are also the CI gates. `pnpm test` runs api vitest only (web has no test script).

## Commit & push

One discrete change per commit, push immediately after each commit (see `docs/repo-history.md` for the full git rules). Pushing to `main` triggers CI + Railway deploys automatically: the CI run itself is a final verification (watch it with `gh run watch`), and `gh run list -R MGM-Laboratory/mgm-website` should show both workflows green.
